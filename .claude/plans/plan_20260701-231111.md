# Plan: Reference Dossier Separation

## Diagnosis

Ten external reference studies currently live under `projects/*-reference/`.
`projects/AGENTS.md` defines that subtree as client project input, acceptance, and
delivery evidence, while `design-intelligence/` is the consulted reference corpus.
`checks/learning-review.mjs` scans all `projects/*` directories and `checks/copy-lint.mjs`
scans the whole `projects` tree, so reference studies are coupled to client-project
quality gates.

## Tasks

1. Spec and contract update
   - Files: `specs/reference-dossier-separation.spec.md`, root/docs ownership text.
   - Acceptance: spec is approved and names executable verification.

2. Move reference dossiers
   - Files: move `projects/*-reference/` to `design-intelligence/references/*/`.
   - Acceptance: `projects/` contains only `_template` and future client folders; reference studies keep their five markdown files.

3. Update gates and tests
   - Files: `checks/learning-review.mjs`, `tests/learning-program.test.mjs`.
   - Acceptance: learning review distinguishes client projects from reference studies; copy lint remains scoped to client `projects/`.

4. Update DOX/documentation indexes
   - Files: `projects/AGENTS.md`, `design-intelligence/AGENTS.md`, `design-intelligence/references/AGENTS.md`, `AGENTS.md`, `constitution.md`, `README.md`.
   - Acceptance: contracts route new reference studies to `design-intelligence/references/`.

## Test Strategy

Run targeted checks first:

- `npm run spec:validate`
- `npm run test:learning`
- `npm run check:learning`
- `npm run check:copy`

Then run broader gates that are likely to catch drift:

- `npm run check:structure`
- `npm run check:design`
- `npm run check`

## Sequencing

Tasks 1 and 2 precede gate edits. Task 3 and task 4 can be reviewed independently
once the move is complete. Debug failures by updating the spec, owning contracts,
or executable checks before changing implementation behavior.
